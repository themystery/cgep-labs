# CGE-P GRC Engineering Labs

This repository documents my hands-on lab journey through the **CGE-P (Certified GRC Engineer – Practitioner)** course. The labs focus on bridging the gap between traditional Governance, Risk, and Compliance (GRC) practices and modern cloud engineering by translating security and compliance requirements into repeatable, automated, and testable technical implementations.

Throughout the series, I work with technologies such as **AWS, Google Cloud Platform (GCP), Terraform, Infrastructure as Code (IaC), IAM, encryption, key management, logging, and cloud storage** to explore how security controls can be embedded directly into cloud infrastructure.

The labs demonstrate practical concepts including:

* **Compliance by Design** – Building security requirements into resources from the beginning rather than validating them only after deployment.
* **Infrastructure as Code (IaC)** – Using Terraform to create consistent, repeatable, and version-controlled infrastructure.
* **Reusable Compliance Modules** – Developing modules that allow multiple environments, such as development and production, to inherit a consistent security baseline.
* **NIST Control Implementation** – Translating controls such as **AC-3, AU-11, CM-6, SC-12, SC-13, and SC-28** into technical cloud configurations.
* **Cloud Security** – Implementing encryption, IAM, key rotation, secure storage, logging, and hardened configurations across AWS and GCP environments.
* **GRC Engineering** – Moving beyond manual evidence collection toward automated control implementation, validation, and continuous assurance.

The purpose of this repository is not simply to document completed labs, but to demonstrate my continued development at the intersection of **GRC, NIST RMF, cloud security, DevSecOps, and security automation**.

As an RMF/GRC professional, this journey is helping me better understand how compliance requirements can be translated from written control statements into **technical, measurable, and repeatable security outcomes**.

> **The goal is not just to prove compliance after deployment—it is to engineer environments where secure and compliant configurations become the default.**
